# BDC-VarLib

**BDC Variable Library**: a [LinkML](https://linkml.io/)-based variable library for [BioData Catalyst](https://biodatacatalyst.nhlbi.nih.gov/) datasets. Different studies often capture the same clinical concept as separate dbGaP variables. Atrial fibrillation, for instance, is asked as a distinct question in ARIC, CHS, FHS, MESA, and several other cohorts, each with its own `phv` accession. BDC Variable Library groups those related variables into a single slot per concept, identified by its ontology code (for example `MONDO:0004981`) and annotated with exactly which studies, datasets, and variables it pools together. Concepts are grouped into classes that follow the BioData Catalyst Harmonized Model (BDCHM), such as `Condition`, `MeasurementObservation`, and `DrugExposure`.

The library comes in two forms:

- **Schema** (`src/bdc_varlib/schema/`): LinkML modules, one per BDCHM class,
  used to build the documentation site.
- **Data** (`src/bdc_varlib/data/`): JSON catalogs, one per ontology prefix,
  in the format the study-palette portal reads
  ([portal-varlib contract](portal-varlib/README.md)).

📖 **Documentation:** [tis-lab.github.io/BDC-VarLib](https://tis-lab.github.io/BDC-VarLib)

🔗 **Source data:** generated from RTI International's
[NHLBI-BDC-DMC-HV / priority_variables_transform](https://github.com/RTIInternational/NHLBI-BDC-DMC-HV/tree/main/priority_variables_transform)

## Structure

### Schema (`src/bdc_varlib/schema/`)

- `bdc_varlib.yaml`: umbrella schema; imports every class module.
- `bdc_varlib_common.yaml`: enums shared across classes, so each module
  is self-contained and loadable on its own.
- `bdc_varlib_<class>.yaml`: one module per BDCHM class (for example
  `bdc_varlib_condition.yaml`, `bdc_varlib_measurement_observation.yaml`).
  See the [documentation site](https://tis-lab.github.io/BDC-VarLib) for the
  full module list and statistics.

### Data (`src/bdc_varlib/data/`)

One catalog per concept CURIE prefix, named `varlib_catalog_<prefix>.json`:

| File | Concepts | Labels from |
|---|---:|---|
| `varlib_catalog_mondo.json` | 55 | MONDO release |
| `varlib_catalog_oba.json` | 54 | OBA release |
| `varlib_catalog_hpo.json` | 18 | HP release |
| `varlib_catalog_omop.json` | 68 | not yet (code only) |
| `varlib_catalog_rxcui.json` | 58 | not yet (code only) |
| `varlib_catalog_atc.json` | 27 | not yet (code only) |
| `varlib_catalog_ndfrt.json` | 12 | not yet (code only) |
| `varlib_catalog_vandf.json` | 9 | not yet (code only) |
| `varlib_catalog_mesh.json` | 2 | not yet (code only) |

Each catalog is a `PortalVariableCatalog` with:

- **integrated variables**: one per concept and BDCHM class
  (ID `bdchm:<Class>/<CURIE>`);
- **compound variables**: one per study and HV spec block that derives the
  concept (ID `hv:<file>#<block>/<CURIE>`);
- **single variables**: the dbGaP source variables (ID `dbgap:phv…`), with
  name, description, type, units and values when dbGaP details are fetched;
- **studies**, **concepts** and **sources** referenced by the above.

Supporting files:

- `portal-varlib/`: the portal contract (`portal-varlib.yaml`) and its
  validator, pinned from study-palette PR #72 (see `PINNED.md`).
- `scripts/labels_manual.tsv`: hand-entered labels (`curie`, `label`,
  `source`) for codes no ontology release covers.

### Labels for non-OBO codes

Codes outside the OBO ontologies (OMOP, RxCUI, ATC, NDFRT, VANDF, MeSH) do
not get a label yet. `--ontology` only reads the MONDO, HP and OBA releases.
Every other code goes into its catalog without a `label` unless it is added
to `scripts/labels_manual.tsv`, which is currently empty.

The catalogs still pass validation, because the portal-varlib contract makes
the label optional ("omit when unavailable"). But 176 of the 303 concepts
have no name, so the portal shows only their codes.

| Prefix | Unlabeled | Possible label source | Status |
|---|---:|---|---|
| OMOP | 68 | BDCHM enums (`bdchm.yaml`) | Text available for all 68 |
| RxCUI | 58 | RxNav (NLM RxNorm API) | API available; not yet added |
| ATC | 27 | RxClass (NLM drug-class API) | API available; not yet added |
| NDFRT | 12 | No current API (NDF-RT API retired) | Gap: manual labels |
| VANDF | 9 | Unclear | Gap: manual labels |
| MeSH | 2 | NLM MeSH RDF API | API available; not yet added |

Planned order of label sources: OBO release, then BDCHM enums, then NLM
APIs (cached, like the dbGaP details), then `scripts/labels_manual.tsv`.
Codes with no verified label will keep leaving `label` out.

## Development

### Schema and documentation

The schema files are generated by `scripts/build_bdc_varlib.py`. Re-run it
after the source repository changes:

```bash
python3 scripts/build_bdc_varlib.py --outdir src/bdc_varlib/schema --stats-out docs/stats.md
pytest tests/test_schema.py           # validate the schema
just gen-doc && mkdocs serve          # preview docs at http://127.0.0.1:8000/BDC-VarLib/
```

Optionally pass `--labels labels.tsv` (CURIE and label, tab separated) to use
ontology labels as concept names.

### Data catalogs

The catalogs are generated by `scripts/build_varlib_catalog.py`. It reads the
HV specs, adds ontology labels and dbGaP details, validates every catalog
against the portal contract, and writes nothing if any catalog fails.

```bash
just data                             # build all catalogs (downloads HV main)
BDC_HV_REPO=../NHLBI-BDC-DMC-HV just data   # build from a local HV clone
just test-data                        # test the catalogs only
```

Or call the script directly:

```bash
python3 scripts/build_varlib_catalog.py --ontology --dbgap
python3 scripts/build_varlib_catalog.py --repo-dir ../NHLBI-BDC-DMC-HV --ontology --dbgap
python3 scripts/build_varlib_catalog.py --ontology --dbgap --dbgap-only ARIC   # quick dbGaP test
```

| Option | Effect |
|---|---|
| `--repo-dir` | use a local HV clone instead of downloading |
| `--ontology` | add MONDO, HP and OBA labels from their releases |
| `--manual-labels` | extra labels TSV (default `scripts/labels_manual.tsv`) |
| `--dbgap` | add variable details from dbGaP data dictionaries (cached) |
| `--dbgap-only` | fetch dbGaP details for the named studies only |
| `--catalog-dir` | output folder (default `src/bdc_varlib/data`) |

Without `--dbgap`, single variables use the `phv` accession as their name
and say so in a comment. Codes with no verified label leave `label` out, as
the contract requires.
